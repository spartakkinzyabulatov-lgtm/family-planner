# Развёртывание

## Что уже разрешено
Создать новое приложение и выложить страницу на GitHub Pages. Общая архитектура согласована 25.11.2026.
Настройки сервера разрешается менять только после отдельного согласования конкретных команд.

## Подготовленная команда — пока НЕ запускалась
```sh
ssh -t server 'bash /root/workspace/Приложения/family-planner/deploy/install.sh'
```

Установщик доступен на сервере благодаря существующей синхронизации рабочей папки.
Он отказывается перезаписывать существующие пути и конфигурации:
- устанавливает Caddy из официального репозитория Ubuntu;
- отключает только только что установленную стандартную службу Caddy, запускает отдельную family-planner-proxy;
- создаёт пользователя family-planner, каталог программы /opt/family-planner и закрытую базу /var/lib/family-planner/data.sqlite;
- запрашивает PIN в терминале и сохраняет только его PBKDF2-хеш, не сам PIN;
- добавляет отдельные службы systemd для API и HTTPS;
- открывает 80/tcp и 443/tcp в UFW для HTTPS и выпуска сертификата;
- получает сертификат для family.193.32.200.27.sslip.io. Записи семьи доступны только после авторизации.

## Публикация страницы
config.js содержит только публичный HTTPS-адрес API. Пароль в файл не записывать.
Публиковать из main, корень; служебная почта GitHub noreply.
В production нет демонстрационных семейных записей.

## Проверка
`python3 -m unittest discover -s tests -v`
`node --test tests/model.test.mjs tests/vault.test.mjs`
`bash -n deploy/install.sh`
Локальный стенд: `python3 tests/dev_server.py` — одноразовые данные и тестовый пароль, не семейный пароль.
Проверить два контекста браузера, отключение сети, перезагрузку и доставку очереди после включения сети.

## Хранение и восстановление
SQLite и сеансы лежат вне синхронизируемой рабочей папки. Резервная копия через SQLite backup API, доступ только владельцу службы. Для восстановления необходим серверный файл базы; браузерная копия шифруется PIN.
Не очищать данные браузера при наличии ожидающих отправки изменений.
